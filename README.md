# 六耳（LiuEr）

本地部署的主动反诈骗智能体系统。中文优先、语音与文本双通道、模型推理全部走本地 Ollama。

**仅用于经授权的防御场景。** 系统本身不发起攻击、不拦截未授权流量、不提供任何绕过平台风控的手段。使用前请确认接入侧具备合法的转接能力，并自行评估当地法律与平台条款。

## 关于名字与致谢

取自《西游记》中的**六耳猕猴**——与孙悟空形貌无二的拟声高手，观音、玉帝的照妖镜、谛听皆不能辨，唯如来识破。原著对他的判词是：

> 善聆音，能察理，知前后，万物皆明。

这十二个字就是这个系统的规格书：会听（情报提取）、能辨（话术识别）、知前后（会话状态记忆）、皆明（全局情报视图）。而「法不传六耳」这句老话，本身就带情报色彩。

本项目是**独立实现的开源工具**，与任何同名或近名的商业公司没有隶属、授权或代码关系。架构上的关键思路——双层提示结构——来自麦考瑞大学公开发表的论文《Bot Wars Evolved》（2025-03），本项目按其公开描述做了独立实现。

项目不含任何第三方专有代码。

## 它解决什么问题

传统反诈都在提高受害者的警惕性，也就是把防守成本压在个人身上。LiuEr 换了一个支点：不去教育用户，而是主动与诈骗方接触，在对方拿到收款基础设施信息的那一刻截断。

核心 KPI 不是浪费了多少时间，而是套出了多少可封堵的情报：收款账号、加密钱包、钓鱼域名、被冒用的品牌。

### 双层提示结构

对应麦考瑞大学《Bot Wars Evolved》（2025-03）公开的架构。

**第一层构造身份**：年龄、性别、职业、口音、性格、数字熟练度、生活细节、以及 2 到 4 个固定「破绽」。破绽是关键——骗子会试探对方是否好骗，agent 表现出一致的破绽才能通过验证。常见破绽包括忘事、信号不好、按错键、找不到老花镜、手机太卡。

**第二层定策略**：当前处于哪个阶段（试探、信任、收割、防御、收尾）、本次要套什么情报、用什么话术拖延、以及何时结束。对话目标不是「回答上一句」，而是「让对方说出他必须说的信息」。

### 第二层内部：12 模态轮询

固定策略会让模型形成话术惯性，几轮之后回复高度重复，有经验的诈骗方会察觉对面「在按套路走」。所以第二层不是固定策略，而是**每轮切换行为模态**：

```
语境 → 个人情况 → 反身性格 → 同理心 → 爱心安抚 → 耐心
     → 诡辩 → 套话 → 耐心 → 反身性 → 同理心 → 爱心安抚
```

「耐心 / 反身 / 同理心 / 爱心安抚」各占两席，权重高于其他模态。这四类属于**柔性模态**，能把对话拉长而不引起警觉，是拖延战术的主要载体；「诡辩 / 套话」是**刚性模态**，出现过多会让对方起疑。

三条调度约束：

1. **早期不主动套话** —— 未进入收割阶段前过滤掉「套话」，避免过早暴露目的
2. **刚性模态不连续** —— 诡辩、套话不会连着出现
3. **对方起疑时收敛** —— 怀疑度超阈值后强制切到柔性模态，停止追问

| 模态 | 作用 |
|---|---|
| 语境 | 用这一代人的共同经验理解对方，时代参照物自然流露 |
| 个人情况 | 用自身经历比对对方说的事 |
| 反身性格 | 自我质疑——**怀疑自己，而不是怀疑对方** |
| 同理心 | 对对方表达理解，让对方卸下防备 |
| 爱心安抚 | 长辈式关怀，语气温而不煽情 |
| 耐心 | 不急不躁，拖延的核心载体 |
| 诡辩 | 用自己的逻辑追问，逼对方把细节说出来 |
| 套话 | 主动索取可验证的硬信息：工号、单位全称、回拨号、收款账户 |

**「反身性格」是最关键的一条。** 受过良好教育的人，怀疑永远指向自己而不是对方——「我是不是没听懂」「是不是我落伍了」。这条写实了人格才有说服力；写反了（让角色去质疑对方）会立刻暴露机器身份。

### 短期思考（回复前先想一下）

默认开启。每一轮回复前，模型先写一小段**中文内心活动**（3 条以内、80 字以内）：对方这句话想让我做什么、我这轮最该达到什么目的、我该怎么说。然后这段内心活动作为「不可外泄的私有上下文」注入系统提示，模型再开口说话。

为什么不用模型的原生思考链：实测 `qwen3.5:4b` 在 Ollama 下开 `think=true`，思考链不收敛——`num_predict=416` 时 416 个 token 全被用于思考、正文为空；加到 1024 时思考仍达 3.9K 字符、正文依旧空、单次耗时 11 秒。实时对话既要低延迟又要正文非空，所以默认走可控的 `brief` 双阶段。

三种模式（`llm.think_mode`）：

| 模式 | 做法 | 实测延迟 | 适用 |
|---|---|---|---|
| `brief`（默认） | 双阶段，思考受 `think_budget` 硬限制，中文、结构化 | 约 1.5 秒 | 实时语音与文本，推荐 |
| `native` | Ollama 原生 `think=true`，思考走 `thinking` 字段 | 约 10 秒且常降级 | 换用能稳定收敛思考的模型时 |
| `off` | 不思考，直接生成 | 约 0.8 秒 | 极致低延迟 |

安全与稳定性设计：

- 思考与正文严格分离。思考只进审计与看板，**绝不发送给对方**
- 思考超时（默认 8 秒）或失败自动降级直出，不阻塞回复
- 正文为空时自动去掉思考注入重试一次
- 正文中万一出现「内心活动」字样会被 `_sanitize` 剥离，避免暴露机器身份

看板上每条 Agent 消息下方可折叠查看该轮的短期思考；`POST /api/chat` 同时返回 `thinking` 字段。

### 人格档案

`profiles/` 下放具体人物档案，用于「为家中易受骗的长辈建一个数字诱饵」的场景。

```bash
python -m liuer --profile profiles/你的档案.yaml
```

档案字段直接对应上表各模态。**隐私优先：除 `template.yaml` 外，目录内所有 `*.yaml` 默认不进版本库**，详见 `profiles/README.md`。

### 情报管道

按延迟排序设计：

1. **规则层先跑**：卡号、BSB 账号、加密钱包、域名、短链、IP 直连、手机号、邮箱。正则保证毫秒级，置信度靠语义上下文加权（对方说「账号是」时置信度更高）。
2. **LLM 层后跑**：只补规则拿不到的语义信息——冒充品牌、话术类型、团伙结构。带 8 秒超时，超时直接用纯规则结果。
3. **实时推送**：置信度超过阈值即推送给客户，不等会话结束。

情报内容是可直接致害的信息，落盘前全部加密。

## 快速开始

```bash
# 安装
./scripts/setup.sh        # macOS / Linux
scripts\setup.bat         # Windows

# 准备模型（首次约 10GB）
ollama pull qwen2.5:14b-instruct
ollama pull qwen2.5:7b-instruct

# 启动
python -m liuer
```

打开 http://127.0.0.1:8787

模型未就绪时系统仍可启动。风险检测、人格生成、规则情报抽取完全可用，只有人格对话生成会降级为兜底话术。

## 配置

全部配置在 `config.yaml`，无硬编码路径。

| 段 | 关键项 |
|---|---|
| `deployment` | `mode` 部署形态、`offline` 纯离线开关 |
| `llm` | `chat_model` 人格对话模型、`extract_model` 情报抽取模型、`think_mode` 短期思考模式 |
| `persona` | `library_size` 人格库规模、`accent_presets` 口音 |
| `intel` | `min_confidence` 推送阈值、`push_channel` 推送方式 |
| `channel.voice` | `sip` 接入配置、`asr` / `tts` / `vad` 组件选型 |
| `channel.text` | 通道适配器、蜜罐池大小 |
| `security` | 加密密钥、音频留存天数 |

部署形态支持 `local` / `private_cloud` / `hybrid`，云无关。

## 语音通道

组件全部可插拔，缺任一项自动降级，不阻塞核心反诈逻辑：

- **VAD**：`silero`（推荐）或内置能量阈值
- **ASR**：`funasr` / `faster-whisper` / `whisper`，中文优先 FunASR
- **TTS**：HuggingFace 开源模型，见下表

### 语音合成（HuggingFace 模型）

按 8GB 显存（且本地 LLM 已占约 3GB）选型：

| 引擎 | 显存 | 许可证 | 特点 |
|---|---|---|---|
| **MeloTTS**（默认） | 0（CPU 实时） | MIT 可商用 | 几百 MB，与 LLM 互不抢资源 |
| **ChatTTS** | 2-3GB | **CC-BY-NC 非商用** | 对话感最强：自带语气词、停顿、笑声，最贴合老年人格 |

CosyVoice2 需 6-8GB 显存，与 LLM 无法共存于 8GB 卡，未纳入。

```bash
# 默认方案（CPU）
pip install git+https://github.com/myshell-ai/MeloTTS.git   # 需先装 espeak-ng
pip install soundfile numpy

# 高质量方案（GPU，个人/研究用途）
pip install chattts
```

模型文件**首次运行时自动从 HuggingFace 下载**；国内网络默认走
`hf-mirror.com` 镜像（`channel.voice.hf_mirror: true`）。

配置：

```yaml
channel:
  voice:
    tts:
      provider: melo      # melo | chattts | mock
      device: auto        # auto | cuda | cpu
    hf_mirror: true
```

试听接口（装好依赖后快速验证）：

```bash
curl -X POST http://127.0.0.1:8787/api/voice/tts \
  -H "Content-Type: application/json" \
  -d '{"text":"哎哟，这好事我可得记下来，您是哪个科室的同志啊？","mission":{"accent":"putonghua"}}'
```

返回 WAV（base64）。`engine` 字段显示实际使用的引擎；
依赖未装时会降级为 MockTTS 并在 `is_mock` 中标记。

口音→音色映射：MeloTTS 内置中文音色单一，以语速区分口音气质；
ChatTTS 用确定性随机种子生成说话人向量（如东北 1966、粤语影响 2249）。

诚实声明：合成质量未在 CI 中验证（模型需本机下载），接线与降级逻辑有测试覆盖（`tests/test_voice.py`）。

端到端延迟的三个主要杠杆：VAD 静音阈值、流式生成、句级提前合成。

SIP 接入支持 `aiortc`。FreeSWITCH dialplan 片段见 `channel/voice/sip.py` 的 `freeswitch_dialplan_xml()`。

## 任务下发

客户可对特定对端下发任务，改变 agent 的核心目标：

```json

  "peer": "13800138000",
  "intent": "harvest_crypto_wallet",
  "target": "某交易所",
  "notes": "优先套 USDT TRC20 地址"

```

可用意图：`none`、`harvest_bank_account`、`harvest_card_number`、`harvest_crypto_wallet`、`harvest_domains`、`harvest_phone_numbers`、`map_network`、`brand_impersonation`。

## 合规

- 仅用于经授权的防御场景，接入侧需具备合法的转接能力
- 外部平台适配器仅提供接入骨架，不含任何规避平台风控的手段
- 蜜罐号码默认关闭，启用前请确认符合当地电信法规
- 情报字段加密存储，音频按 `retention_days` 留存
- 人格库全部为虚构角色，不对应任何真实个人

## 已知局限

- ASR/TTS 组件缺失时语音通道降级为文本模式
- `qwen3.5:4b` 的原生思考链不收敛，故默认用 `brief` 短思考；换模型后可试 `native`
- `agent-war` 风险尚未解决：诈骗方使用 AI 对话时，拖延战术的价值会被削弱
- 情报规则以中国大陆常见格式为主，海外格式覆盖有限
- 置信度评分基于规则加权，未经真实数据校准
